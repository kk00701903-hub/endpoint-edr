# 통합 테스트 · 수준 평가 · 추가 과제 (2026-10-02)

이 문서는 전체 구간을 실제로 연결해 시험한 결과와, 글로벌 상용 제품 대비 현재 수준, 그리고 운영 전에 보강할 항목을 정리한 것이다.
코드는 이 점검에서 고치지 않았다(아래 "실험으로 확인"은 임시 사본에서만 시험).

## 1. 비교 기준

- 이 시스템은 EDR(보안 관제)이라 CRM·그룹웨어와 **기능**을 맞댈 수 없다. 그래서 두 축으로 나눠 본다.
  - **기업용 소프트웨어 기본기** — Salesforce·HubSpot(CRM), Microsoft 365·Google Workspace(그룹웨어) 같은 글로벌 SaaS 가 공통으로 갖춘 것: 로그인 보안(SSO·MFA), 권한·구성원 관리, 감사 기록, 알림, API·연동, 내보내기·보고서, 접근성, 성능, 운영 신뢰성, 품질 관리.
  - **EDR 고유 기능** — CrowdStrike Falcon, Microsoft Defender for Endpoint, SentinelOne 같은 상용 EDR 의 공통 기능.
- 사내 전용·무료 오픈소스·수동형(차단 없음)이라는 설계 조건 때문에 일부러 빼 둔 기능(차단·격리 같은 대응, 과금, 다국어)은 감점하지 않는다.

## 2. 통합 테스트 결과

### 시험 환경
- 서버 1대 사양: CPU 2코어, 메모리 7GB (DB·수집 서버·콘솔·부하 발생기를 한 대에서 같이 실행)
- PostgreSQL 16 + PostgREST(Supabase API 흉내) + 실제 `ingest`·`enricher` 바이너리(DB 역할 `edr_ingest`·`edr_enricher` 로 접속) + 운영 빌드 콘솔

### 접근성(axe-core, WCAG 2.1 AA, 13개 화면 × 밝은·어두운 테마)
- 글자 대비 부족: 보조 글자색 `--muted` 가 흰 바탕에서 4.28:1, 옅은 회색 바탕에서 3.99:1(기준 4.5:1). ATT&CK 칸의 기법 번호, 어두운 테마 메뉴 그룹 이름도 기준 미달.
- 링크에 쓸 수 없는 `aria-pressed` 속성(경보 화면 심각도 필터), 관제 레인 차트 안에 누를 수 있는 요소가 겹쳐 있음.

## 3. 발견한 문제 (심각도 순)

| # | 심각도 | 문제 | 근거 | 제안 |
|---|---|---|---|---|
| A | **긴급** | 여러 PC 가 동시에 보내면 수집 서버가 DB 교착 상태(deadlock)에 빠짐 | PC 300대 동시 전송 시 4분 넘게 600건을 못 끝내고 교착 320건. 같은 프로그램(chrome.exe 등) 해시를 여러 PC 가 동시에 기록하면서 잠금 순서가 엇갈림 | 해시 기록 순서를 정렬하고, 이미 1시간 안에 본 해시는 갱신하지 않기. **임시 사본으로 시험: 교착 0, 같은 부하를 5초에 처리** |
| B | 높음 | 늦게 도착한 로그온 실패는 무차별 대입 탐지(EDR-AUTH-001)에서 빠짐 | 규칙이 "발생 시각 기준 최근 10분"만 본다. 네트워크가 끊겼다가 스풀로 늦게 올라온 실패 15회가 탐지되지 않음(실패+성공 규칙은 정상 탐지) | 발생 시각 창은 유지하되 "이번에 새로 들어온 행" 기준으로 계산 |
| C | 높음 | pg_cron 이 없으면 파티션 생성·보존 정리가 멈춤 | 대체 경로(enricher)는 탐지만 대신 실행한다. 미리 만든 파티션(+2개월)이 끝나면 수집 저장이 실패 | enricher 대체 루프에 파티션 생성·정리 추가, 콘솔에 "마지막 탐지·파티션 작업 시각" 표시 |
| D | 높음 | 로그인 보안이 이메일·비밀번호뿐 | MFA·SSO 연결 없음 | Supabase MFA(TOTP) 필수화, 사내 계정(Microsoft Entra ID 또는 Google) SSO 연결 |
| E | 중간 | 감사 기록 없음 | 누가 경보를 종결했는지, 규칙을 껐는지, 등록키를 만들었는지 남지 않음(메모만 남음) | `audit_log` 테이블 + 트리거, 설정 화면에 조회 |
| F | 중간 | 재전송 시 프로세스·연결 기록 중복 | 같은 배치를 다시 받으면 프로세스·연결 행이 두 번 저장됨(헌팅 결과 2배). 보안 이벤트는 정상적으로 중복 제거됨 | 배치마다 ID 를 붙여 이미 받은 배치는 건너뛰기 |
| G | 낮음 | 명령 팔레트에서 장치 이름을 치고 Enter 를 누르면 "계정 프로필"로 감 | `SRV-WEB` 입력 → `/entities/user/SRV-WEB` | 장치 이름과 맞으면 장치를 맨 위에 |
| H | 낮음 | 헌팅에서 `process.name ==` 가 오류 없이 "= 라는 이름 찾기"가 됨 | 연산자 오타를 값으로 받아들임 | 값이 연산자 기호뿐이면 문법 오류 표시 |
| I | 낮음 | 접근성 대비·속성 오류 | 위 접근성 항목 | `--muted` 등 토큰 명도 조정, `aria-pressed` 를 `aria-current` 로 |
| J | 낮음 | 보안 헤더 일부 없음 | CSP·HSTS 없음(X-Frame-Options 등 4종은 있음) | Caddy 에 HSTS, 콘솔에 CSP 추가 |

### 종합
- **잘된 것:** 조사 화면, 성능, 데이터 격리, 수집 서버 방어는 상용 제품에 견줄 만하다. 특히 "화면에서 숨긴 기능을 API 로 직접 불러도 DB 가 막는" 구조는 실제로 확인됐다.
- **부족한 것:** 기업용 기본기(SSO·MFA, 감사 기록, 구성원 관리, 내보내기, 알림 배정, 자동 테스트)가 약하다. 지금 수준은 **"화면은 상용급, 운영 기반은 사내 시범 운영 단계"** 이다.
- **운영 전 반드시 고칠 것:** 문제 A(교착)는 PC 수십 대 이상에서 바로 드러나므로 실제 배포 전에 고쳐야 한다. B·C 도 운영 중 조용히 탐지·수집을 놓치는 유형이라 우선순위가 높다.

## 5. 추가 과제 (권장 순서)

**1단계 — 운영 전 필수**
1. 수집 서버 교착 해소(문제 A) + 같은 시험으로 재측정
2. 늦게 도착한 이벤트 탐지(문제 B), pg_cron 없는 환경의 파티션·보존 작업(문제 C)
3. MFA 필수화 + 사내 계정 SSO(문제 D)
4. 감사 기록(문제 E)
5. 이번 통합 테스트를 저장소에 넣고 CI 로 자동 실행(문제 K)

**2단계 — 기업용 기본기**
6. 구성원 초대·역할 변경 화면, 인시던트 담당자 지정·처리 기한
7. 인시던트 단위 알림(Teams·메일), 하루 요약 메일
8. 헌팅 결과 CSV 내보내기·더 보기·집계(장치별·이름별 개수), "이 쿼리로 탐지 규칙 만들기"
9. 배치 ID 로 재전송 중복 제거(문제 F), 에이전트 전송 묶기(요청 수를 1/3 수준으로)
